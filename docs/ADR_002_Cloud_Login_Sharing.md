# 当前阶段的登录与云端分享方案

2026 年 11 月 3 日，用户将正式登录和云端分享列为优先功能，界面继续使用中文。先沿用已有的 Cloudflare Worker 后端，避免在云端分享尚未运行时同时进行完整后端迁移。开发规格中的 Django 仍是本地单体方案建议；此决定仅确定当前云端路径，并非将原型认定为完整毕设。

## 已实现代码

- 服务端验证 Access JWT 的签名、颁发者、受众、期限与身份；不信任浏览器提交的用户标识。
- 云端 UI 使用已验证邮箱显示账号；退出入口由 Access 提供。未认证请求无法读取私人页面或接口。
- 文件和讲义按已验证身份分区保存到私有 R2。
- 分享必须填写接收者邮箱、内容范围和 1 至 30 天的期限。
- 只读链接使用 256 位随机令牌，存储端仅保存 SHA-256 摘要；仅指定接收者和所有者可以访问。
- 分享可限制为仅摘要或正文加摘要，始终排除私人批注和原文件。
- 替换、撤销、删除讲义和到期会使旧链接不可用。
- 同源校验保护写请求，匿名、跨账号和跨站请求受到拒绝。

## 仍需线上完成

创建 Worker 并连接本仓库，建立私有 R2，启用覆盖全部 Worker 域名和预览地址的 Access 策略，设置 ACCESS_ISSUER 和 ACCESS_AUD，然后部署。接收者也必须被 Access 策略允许；在应用中填写邮箱不会自动扩大网站访问名单。

本地的 127.0.0.1 预览仍然是浏览器本地数据，不会被自动上传。上线后应由用户明确选择需要上传的原件，避免迁移过程中静默外传材料。

不得把本地签名令牌与模拟 R2 测试报告为已完成真实登录或云端分享验收。上线后必须使用两个真实获准账号验证登录、跨设备读取、仅摘要范围、原件隔离、过期和撤销。
